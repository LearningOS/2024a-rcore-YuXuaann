# 简答题

1. SV39 页表项的格式如下：

   - Valid 位（V 位）：  
   位置：位 0  
   功能：标志该页表项是否有效。若 V=1，表示此页表项有效；若 V=0，表示该页表项无效。

   - Read 位（R 位）：  
   位置：位 1  
   功能：指示该页是否具有读权限。R=1 时允许读取，R=0 则不允许读取。

   - Write 位（W 位）：  
   位置：位 2  
   功能：指示该页是否具有写权限。W=1 时允许写入，W=0 则不允许写入。

   - Execute 位（X 位）：  
   位置：位 3  
   功能：指示该页是否具有执行权限。X=1 时允许执行该页内容，X=0 则不允许。

   - User 位（U 位）：  
   位置：位 4  
   功能：标志该页是否为用户态访问。U=1 表示用户态可以访问，U=0 表示仅限内核态访问。

   - Global 位（G 位）：  
   位置：位 5  
   功能：标志该页表项是否对所有地址空间都有效。若 G=1，则该页对所有进程有效；G=0 表示仅在当前地址空间有效。

   - Accessed 位（A 位）：  
   位置：位 6  
   功能：指示该页是否被访问过。硬件在页被访问时自动设置 A=1，操作系统可以使用该位进行页面替换的策略判断。

   - Dirty 位（D 位）：  
   位置：位 7  
   功能：指示该页是否被写入过。硬件在页内容发生写入时自动设置 D=1，操作系统可以利用该位来确定是否需要将页面写回存储器。

   - 保留位：  
   位置：位 8 到位 9  
   功能：这些位是为未来扩展保留的，不在 SV39 页表项中使用。

   - 物理页号（PPN, Physical Page Number）：  
   位置：位 10 到位 53  
   功能：存储物理页号，用于将虚拟地址映射到物理地址。PPN 是物理页地址的高位部分，物理地址通过 PPN 加上页内偏移得到。

   - 保留（Reserved）：  
   位置：位 54 到位 61  
   功能：这些位在 SV39 中未使用，通常保留给将来的扩展。

   - 自定义位：  
   位置：位 62 到位 63  
   功能：可以由软件自定义使用，但在标准的 RISC-V 实现中无特殊功能。

2. 缺页问题

    1. 请问哪些异常可能是缺页导致的？  
    `load/store/instruction page fault`

    2. 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。  
       - `scause`：`scause::FAULT_LOAD_PAGE` 或 `scause::FAULT_STORE_PAGE` 或 `scause::FAULT_FETCH_PAGE`
       - `stval`：缺页的虚拟地址
       - `satp`：页表根指针

    3. 这样做有什么好处？  
    节省性能开销，只有当用户进程需要时，再去申请内存

    4. 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？  
    第三级节点管理 `2MB` 空间，第二级节点管理 `1GB` 空间，第一级节点管理 `0.5TB` 空间，所以大致需要 `20MB` 的内存

    5. 请简单思考如何才能实现 `Lazy` 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。缺页的另一个常见原因是 `swap` 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效  
    在发生缺页异常时，去看访问的页面是否为无效页面，如果是则分配一个物理页，将其映射到对应的虚拟页上，然后从磁盘上读取数据到物理页上

    6. 此时页面失效如何表现在页表项(PTE)上？  
    使用 `A` 标志位可以代表是否在加载应用时访问过

3. 双页表与单页表

    1. 在单页表情况下，如何更换页表？  
    写 `satp` 寄存器，通过改根节点来改页表

    2. 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）  
    使用 `U` 标志位可以代表仅能在用户态访问

    3. 单页表有何优势？（回答合理即可）  
    实现简单，不需要考虑多级页表的问题

    4. 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？  
    在进程切换时或进系统调用时更换页表；在进程切换时更换页表
